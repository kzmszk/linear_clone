# 振る舞いテストの対象

性能改善の前後で、公開API・ビルド済みCLI・ブラウザの結果が変わらないことを確認するためのテストです。内部関数の呼び出し回数やSQLの形には依存させません。行・分岐カバレッジの百分率は未計測です。テスト件数を網羅率として扱いません。

CLIの性能改善では、以下の振る舞いも実Workerとコンパイル済みCLIで検証します。

- `cli-references.test.mjs`: 名前とUUIDを混ぜた参照、担当者のuser ID、非公開teamの拒否、アーカイブ済みprojectの除外。
- `cli-batch.test.mjs`: 逐次実行、引数の分離、名前変更後の再解決、競合・不正入力後の停止、JSON形式のエラー。
- `cli-update-concurrency.test.mjs`: 不正参照と古いversionで保存内容が変わらないこと、状態UUIDの所属検証と作成拒否。

表のパスは `tests/` からの相対パスです。複数の操作をまとめたテストもあるため、1件のテストを1機能と数えません。

## テストの境界

APIテストはローカルの本物のworkerdとSQLite/R2 bindingを使います。CLIはビルド済みファイルを別プロセスで実行します。ブラウザも実Workerを利用し、通信失敗や接続切断だけをテスト側から注入します。DB処理や成功レスポンスを偽物に差し替えて合格にはしません。

通常のローカル試験では本人確認の入口にテスト用ヘッダーを使い、認可処理は製品コードを通します。JWTのテストは実際の鍵で署名し、ローカルJWKSサーバーを使います。Cloudflare Accessサービス自体の可用性を検証するものではありません。

`api.test.mjs` は各テストに新しいWorkerと保存領域を用意します。別のテストで採番が進んでいることを期待しません。拒否の判定では具体的なHTTP statusとerror codeを確認し、500エラーを期待どおりの拒否として通しません。権限テストは「見えないもの」だけでなく「見えるべきもの」も確認します。

再起動テストでは保存領域を残してWorkerプロセスを交換し、最後の後始末だけで領域を削除します。終了を5秒待っても止まらない場合は、そのテストが起動したプロセスグループを強制終了します。

## 性能変更の検証手順

```sh
pnpm check
pnpm test:e2e
```

`pnpm check` はformat・lint・型検査・ビルド・実Worker/CLIテストを含みます。ブラウザテストはそのビルド成果物を使います。性能変更前後で両方を成功させ、変更した経路の対象テストも確認します。

100件の処理だけを再実行する場合は `pnpm test:load` を使います。テスト全体の時間にはWorker起動・ブラウザ起動・検証・後始末が入ります。その時間をアプリの応答時間として比較しません。loadテストの `elapsedMs` も複数段階の要求と保存結果の読取を含み、単発要求のp95ではありません。

## 残っている範囲

- 行・分岐カバレッジの計測。
- 複合フィルターと権限条件を組み合わせた200件超のページ境界。単独の複合条件と、team条件での405件ページングは検証します。
- ログイン期限切れやメンバー除外後の、Web画面内に残るキャッシュの消去。JWT拒否とイベント接続切断・HTTP拒否は検証済みです。
- 保存確定後に応答だけを失った場合の全UI操作の再試行。再起動後の同じ操作IDの再送は別途検証します。
- インポートの各段階で強制中断し再開する網羅的な試験。
- Cloudflare本番での100件同時負荷、Linearとの同条件のレイテンシ比較。

未検証の項目を成功したテスト件数で埋め合わせません。次の性能変更がこの範囲に触れる場合は、その振る舞いのテストを先に追加します。
