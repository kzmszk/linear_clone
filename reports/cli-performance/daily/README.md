# 日常CLI操作の性能改善

FUCHIKOMA-25の追加改善です。未完了一覧・チケット登録・ステータス更新・コメント追加を対象にしています。

改善前はCLI `ee24ac0` とWorker `29cebc45-90b9-4193-b6da-3c8ad3ac146d`。改善後はCLIの変更を含む `3cdbe99` と、weak ETag対応を加えた `a6c11cd` のWorker `dee28639-bda8-40fe-b0b7-79cd00e344e3` です。CLI成果物のSHA-256は各JSONに記録しています。最終CLIは `a6c11cd` のソースを別ディレクトリに取り出して再ビルドし、計測した成果物とSHA-256が一致することを確認しました。[ビルド証跡](clean-build.json)には、既存のインストール済み依存パッケージを使用した条件も記録しています。

すべて `--state Backlog` で同じ20件を取得します。変更後の条件では新しいタイトルと版番号まで照合しています。

改善後の初回165.1msと変更なし159.4msの差は5.7msです。この小さな一覧ではキャッシュ単独の速度改善を強く主張できません。主な改善は参照解決の通信削減で、304の確実な利点は応答本文を転送しないことです。変更後も159.9msだったことから、数msの差には通信の揺らぎが含まれます。最新版かどうかは毎回リモートに確認するため、キャッシュだけを読む時間にはなりません。

[キャッシュ条件の改善前](production-cache-before.json)と[改善後](production-cache-after.json)を保存しています。成功した最終計測で作成した専用workspace4件はarchive済みです。

## 測定条件

- 接続先は `https://linc.kazumasa.workers.dev`。同じLinuxマシンとNode.jsを使用しています。
- `--workspace` にslugを指定し、未完了20件・完了200件の専用ワークスペースを使用しました。
- 時間は子プロセス起動の直前から終了までです。起動、通信、検証、JSON出力を含みます。データ準備と保存結果のAPI照合は含みません。
- 改善前は旧Workerで同一の旧CLIを2組、各10回実行した20標本を集計しました。改善後は新Workerでの新CLIの10標本です。改善前後は別の時間帯なので、ネットワークの変動も含みます。
- 新Workerで旧CLIも交互に実行しています。これはCLIだけの違いを見る補助データであり、旧Workerを含む改善前の代用にはしていません。
- 通信回数と本文バイト数は別の非計測実行で取得しました。ヘッダーやトークン、本文はトレースに保存していません。
- 通常の一覧ベンチマークは初回とキャッシュ済みの実行を含みます。キャッシュ専用ベンチマークでは、初回、変更なし、別クライアントによる更新後を分けています。
- p95はnearest-rankです。新CLIの10標本では最大値になるため、安定した尾部レイテンシの推定には使いません。

途中で旧CLIが `fetch failed` を返した計測は、完了していないため採用せず全体を再実行しました。[失敗と後片付けの記録](failed-run.json)を残しています。表は成功した操作のレイテンシであり、失敗率の評価ではありません。ローカルテストが重なった改善前のslug計測も取り直しています。

## 実装と検証

CLIの既定一覧は、workflow stateの種別がcompleted/canceledでないチケットを取得します。`--all`、`--closed`、明示的な `--state` で表示範囲を選べます。Web・従来のAPI・インポートの既定一覧は維持しています。

workspaceのslug、チームやプロジェクトの名前、ステータス名、チケット番号をWorker側で解決します。通常の登録とコメント追加は1通信、ステータス更新は版番号の確認を残して2通信です。呼び出し元が `--expected-version` を指定した更新は1通信です。競合検出と権限確認は省略していません。

完全な1ページだけをローカルに保存します。アカウント・接続先・条件を分け、毎回認証付きでWorkerに確認します。304なら保存した結果を表示し、変更があれば200で取り直します。変更番号は全体で共有するため、コメントや別workspaceの変更でも再取得する場合があります。差分同期、常駐デーモン、通信失敗時に古い一覧を返す処理は追加していません。

Cloudflareが本番のETagをweak形式に変えることは実際の通信で確認しました。weak形式も同じ検証子として扱う修正を加え、本番で304・転送本文0bytes・保存済み出力との一致を確認しています。

実Workerを使ったAPI・CLI・負荷試験58件、ブラウザーE2E31件が成功しました。weak ETag修正後はキャッシュ4件を再実行しています。100件同時の登録・更新・再送と1件への100競合更新はローカル試験です。formatter・linter・全プロジェクトの型検査と品質検査を通し、既存の制限は緩めていません。[検証の範囲と結果](verification.json)に記録しています。

再送結果の実体への権限確認とworkspaceの一致も検証しています。名前の再利用とアクセス権の剥奪を組み合わせた場合でも、以前の非公開チケットやコメントを再送結果として返しません。

再実行方法は [CLIの性能改善と計測方法](../../../docs/cli-performance.md)を参照してください。
