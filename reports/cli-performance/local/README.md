# ローカルCLIの性能と検証

`linc local` は日常操作をこのマシンのSQLiteに保存し、`local sync` または `local watch` でまとめて送信します。[利用手順](../../../docs/local-cli.md)を参照してください。

同期APIは `c4162be`、CLIと実動作テストは `4053d96` にコミットしました。本番WorkerのデプロイIDは `3e7a41d2-201d-4913-a40c-e0624764f3ad` です。コミット済みソースから別ディレクトリで再ビルドし、計測したCLIとSHA-256が一致しました。[ビルド証跡](clean-build.json)に条件を記録しています。

## ローカルの実Workerで比較した結果

Node.js 26.8.1で、未完了20件・完了200件の同等なworkspaceを2つ用意しました。改善前のCLIとローカルCLIを交互に各10回起動し、プロセス起動から終了までを測っています。初期データ作成・同期・結果照合は日常操作の時間に含めません。計測中は他のビルドやテストを実行していません。

改善前CLIはlocalhostの実Workerへ通信し、サーバー保存完了まで待ちます。ローカルCLIは端末への保存完了までです。クラウドへの通信を含む比較ではありません。

| 操作           | 改善前CLIの中央値 | ローカルCLIの中央値 | ローカルCLIのp95 |
| -------------- | ----------------: | ------------------: | ---------------: |
| 一覧表示       |         69.187 ms |           59.906 ms |        61.533 ms |
| チケット登録   |         73.428 ms |           67.040 ms |        72.353 ms |
| ステータス更新 |         78.010 ms |           67.658 ms |        71.535 ms |
| コメント追加   |         72.703 ms |           65.722 ms |        69.946 ms |

p95は10件の最大値です。長期的な遅延分布を表す値ではありません。[全試行と通信量](benchmark-local.json)を保存しています。一覧の別途トレースでもHTTP通信は0回でした。登録・更新・コメントはネットワークを禁止した実CLIテストで検証しています。

前回の本番CLI計測は一覧168.187 ms、登録174.178 ms、更新214.581 ms、コメント166.934 msでした。[前回の結果](../daily/comparison.json)は参考値です。今回は本番との同時比較ができていないため、この値から本番の改善率や3倍達成を確定しません。

## バッチの保存結果

- 登録・更新・コメント計30操作を1回のPOSTで送り、全操作の反映を照合しました。同期コマンドは134.759 msでした。
- 100件を100個の独立したCLIプロセスで逐次登録する時間は6.642秒でした。
- その100件を1回のPOSTでリモート側へ反映する同期コマンドは189.407 msでした。未送信は0件になり、全件のタイトルとUUIDをAPIで照合しました。

ここでいうリモート側もlocalhostの実Workerです。同期時間はプロセス起動・全操作の保存・スナップショット受信・ローカル反映・通信量トレースの処理を含みます。100件の登録と同期を合わせた時間は約6.831秒です。

HTTP通信をまとめても、チケット・履歴・再送記録のDB書き込みは残ります。DB書き込み数を100分の1にする仕組みではありません。計測用workspaceは2件ともarchiveし、ローカルWorkerの試験領域は終了時に削除しています。

## 検証と本番で残っていること

`pnpm check` は80件成功しました。その後のURL判定の共通化は、型検査・ビルド・対象9件・ブラウザーE2E31件で検証しました。最終差分のformat、lint、複雑度、重複、未使用コード検査も成功しました。[検証記録](verification.json)に初回の失敗と修正内容も残しています。

実CLIでは100件の同時登録、同期中の追加保存、応答消失後の再送、競合、取り下げ、権限変更、定期同期と停止を確認しました。テストは実WorkerとSQLiteを使い、通信断だけを注入しています。

本番は変更のデプロイ前からDB書き込み無料枠を超えており、APIが500を返していました。デプロイ後の初回同期も失敗しています。[観測記録](production-quota.json)にエラーと旧WorkerのIDを記録しています。Cloudflareの無料枠は00:00 UTCにリセットされるため、次の復帰予定は2026年9月23日9時JSTです。[Cloudflareの仕様](https://developers.cloudflare.com/durable-objects/platform/pricing/)

本番の初回スナップショット取得、ローカル変更の本番同期、本番を使った性能比較、FUCHIKOMA-25への後半の結果投稿は未完了です。開始時と設計決定時のコメント2件は投稿済みです。消費内訳は今回のエラーログだけでは特定できていません。

## 再計測

```sh
node scripts/benchmark-cli-local.mjs --trials 10 --output artifacts/private/local-first/benchmark-local-final.json
```

本番が復帰した後は、同じコマンドへ `--url https://linc.kazumasa.workers.dev` を付けます。保存済みのAccessログインを使用し、専用workspaceを作成します。初期データ440件などの書き込みを伴うため、本番無料枠を使う計測は繰り返しません。改善前CLIは保持した `dist/cli/linc-local-before.mjs`、改善後は `dist/cli/linc.mjs` を使用します。
